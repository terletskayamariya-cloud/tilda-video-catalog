# Управление видео через Google Sheets (без кода)

## Что меняется

Раньше редактор вручную изменял JavaScript в video-data.js. Теперь достаточно добавить строку в [Google-таблицу](https://docs.google.com/spreadsheets/d/19kMArx3zurEL-5rOWqPnBpB3jeBfcg2LhvDrAySaNrQ/edit).

Скрипт из Code.gs публикует только видео со статусом **«Опубликовано»**.
Сам каталог и его оформление продолжают работать через существующий video-catalog.js. Исторический массив VIDEO_CATALOG_BLOCKS не меняется.

## Ежедневная публикация

1. Открыть вкладку «Видео».
2. Внизу добавить новую строку: название, ссылку Kinescope, категорию и формат карточки; длительность необязательна.
3. Выбрать «Опубликовано» — видео появится при следующем открытии/обновлении страницы. «Черновик» не показывается.
4. При необходимости указать дату будущей публикации в формате 2026-11-01 15:30 (время Минска).
5. Изменение статуса на «Черновик» либо удаление строки убирает ролик из списка при очередной загрузке страницы.

**Порядок:** последняя строка таблицы выводится первой среди новых роликов. Слайдеры одного вида в соседних строках объединяются.

## Разовая настройка

1. Открыть [Google-таблицу](https://docs.google.com/spreadsheets/d/19kMArx3zurEL-5rOWqPnBpB3jeBfcg2LhvDrAySaNrQ/edit).
2. Открыть «Расширения → Apps Script» и вставить код из [Code.gs](./Code.gs). Сохранить.
3. «Развернуть → Новое развертывание → Веб-приложение».
4. В настройках: «Выполнять от имени — меня», «Кому доступно — все» (включая посетителей без аккаунта Google, если настройка доступна). Разрешить доступ скрипту к таблице.
5. Скопировать адрес веб-приложения, заканчивающийся на /exec.
6. Открыть T123 видеоблога в Tilda, после существующей строки подключения video-data.js и до video-catalog.js вставить:

    <script src="URL_ВЕБ-ПРИЛОЖЕНИЯ_APPS_SCRIPT_С_ОКОНЧАНИЕМ_/exec"></script>

7. Опубликовать страницу Tilda один раз.
8. Проверить публикацию нового ролика, фильтры, мобильную версию, слайдеры, плеер и «Загрузить ещё».
9. Когда новая схема подтверждена, сохранить копию старого VIDEO_CATALOG_NEW_VIDEOS, а в основном video-data.js оставить пустой массив. НЕ менять VIDEO_CATALOG_BLOCKS.

## Как работает миграция

Текущий T123 уже подключает video-data.js перед video-catalog.js. Новая строка подключения запускает Google Apps Script между ними: статические новые записи перезаписываются данными из таблицы ДО запуска рендерера. Это предотвращает дублирование.

Пока интеграция ещё не включена, сайт остаётся на текущей статической версии. Если Apps Script временно недоступен и его строка не выполнится, старые новые видео остаются временным fallback; после очистки статического массива — новые записи могут временно отсутствовать. Исторический каталог продолжит отображаться.

## Доступ и безопасность

- Только приглашённые редакторы могут изменять Google-таблицу.
- Публичным является лишь скрипт, отдающий исключительно опубликованные записи; нельзя добавлять в него секреты/контактные данные.
- Скрипт не принимает запись/удаление и не требует клиентских токенов.
- Строки с некорректными ссылками Kinescope, неизвестной категорией или невалидной датой пропускаются.
- Изменение строк таблицы не требует нового развертывания Apps Script. Изменение самого Code.gs требует выпуска новой версии веб-приложения.
- Обратите внимание: до публикации нового веб-приложения и правки T123 интеграция НЕ активна.

## Откат

Удалить только строку с URL Apps Script из T123 и опубликовать страницу; сайт вернётся к данным video-data.js. Если старый массив уже был очищен, перед откатом восстановить его из сохранённой копии/истории GitHub.
